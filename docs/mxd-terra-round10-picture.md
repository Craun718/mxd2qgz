# Terra 第十轮：StdPicture 头与解码器首层分派

## 对象和证据范围

目标是 ArcGIS Desktop 10.1.3035 安装介质携带的 Microsoft OLE 分发件，而非已证实由 ArcMap 实际加载的系统 DLL。复算 `Setup1.cab` 已提取条目 `Global_System_OLEAUT32_f3.8C0C59A0_7DC8_11D2_B95D_006097C4DE24` SHA-256 为 `baeb2f7c1b8be56738d34e1d1ddf8e0eebd3a633215dc1575e14656be38b939d`；PE 机器 `0x14c`（x86），ImageBase `0x65340000`，资源 InternalName `OLEAUT32.DLL`、FileVersion `2.40.4275`。固定版本 `2.40.4275.1` 见[前轮记录](mxd-terra-host-ole.md)。文件身份与摘要不证明签名或实际加载路径。

本轮直接复读该文件、已有 `temp/terra-host-ole/` 反编译和汇编，独立用 PE 虚拟地址读取下列 16 字节标识。前轮在仓库独立目录以 JDK 25、Ghidra 12.2 分析：Ghidra 桥接工具 6.9.0 因 UNIX socket `Operation not permitted` 未产生函数 Evidence ID，继而用隔离 pyghidra 生成伪代码并以 objdump 校验；未使用共享 Ghidra 桥接工具。此处引用的伪代码只是反编译产物，参数不可靠处以汇编为准。既有证据已足以回答本轮首层分派，无需再次启动分析。

## 第二字和循环

SaveHeader `0x653a1071` 在 `0x653a1084` 构造 DWORD `0x0000746c`，`0x653a108c` 写 4 字节，即 `6c 74 00 00`；后续另写长度。Load `0x653a01ce..0x653a0221` 先读 WORD 并比较 `0x746c`，匹配后将第二 WORD 读到同一临时槽，只检查读取状态；随后在另一槽读 DWORD 长度。`0x653a0227` 检查长度，非零时记录流位置并回到 `0x653a01ce`，下一轮首字覆盖第二字；零长度则清零对象 `+0x4c/+0x1c` 并返回。因而可以定性为**该实现的写侧恒为零、匹配头的读侧忽略其值**，不能从此得出业务名称、其他版本语义或任意非零值的运行成功。

循环允许再次遇到 `0x746c`；非头首字转入探测并涉及 seek 和长度处理。外层声明长度、内层头和最终原生消费边界不能简单等同；现有 Rust 读取器只消费一个头和其声明长度的原始载荷，不模拟嵌套头、无头探测、原生解码或其流位置行为。

## 首 WORD 到直接入口

地址均为上述 DLL 虚拟地址，数值为小端 WORD。匹配仅选择入口，不验证图片完整性。

| 首 WORD | Load 静态分派与直接处理 |
| --- | --- |
| `0x4d42` | `0x6539f482` 读 54 字节；内部 DWORD 为 `0x544c5743` 或 `0x544c5747` 时调用 `0x653a3162`，否则调用 `0x653a2811`。短读与读取错误分别有失败路径。 |
| `0x4947`、`0x6967` | 调用 `0x653a3162`，组件标识 `{3B7E1A45-7776-11CF-B751-00AA00BDD7E0}`；前缀与 GIF 一致。 |
| `0xd8ff` | 调用 `0x653a3162`，组件标识 `{3B7E1A44-7776-11CF-B751-00AA00BDD7E0}`；字节 `ff d8` 与 JPEG 一致。 |
| `0x0001` | `0x6539f7dc` 读头探测 `0x464d4520`；匹配调用 `SetEnhMetaFileBits` 并置类型 4，否则调用 `0x6539f5b9` 创建元文件并置类型 2。首字不能独立区分两者。 |
| `0xcdd7` | `0x6539f8ad` 核对 DWORD `0x9ac6cdd7`、读取附加头，调用 `0x6539f5b9`，再据边界和单位数计算尺寸。 |
| `0x0000` | `0x653a0137` 调用 `0x6539fd93`，检查 6 字节目录头：保留字为零、类型为 1 或 2、数量非零，再处理目录项；成功置类型 3。该分支不是空图。 |
| 其他 | `0x653a03b4` 设置 `0x800a01e1`；后续定位和错误处理可能影响最终返回。 |

BMP 特殊分支传给共同入口的标识为 `{ED9A4150-9E00-11CF-B57C-00AA00A71D1A}`。`0x653a3162` 使用传入标识创建组件，查询 `{00000109-0000-0000-C000-000000000046}` 和 `{CF203F90-A20E-11CF-B57D-00AA00A71D1A}`，传入流并循环调用接口；创建时请求标识 `{CDBF2040-C624-11CF-B584-00AA00A71D1A}`。这些 GUID 由 PE 字节直接按 GUID 小端字段解出，组件实现、注册来源、内部格式算法及完整错误传播未在本轮验证。其他入口的细节及伪代码局限见[前轮记录](mxd-terra-host-ole.md)。

## 实现、验证和 TODO 判定

`read_std_picture_body_10_1` 保留第二字及外层声明范围内全部字节，未知前缀也保留；本轮不将首字识别当成图片有效性检查，也不更改生产读取器。新增 `tests/terra_round10_picture.rs`，以合成的 BMP/GIF 两种大小写首字、JPEG、两种元文件、图标、未知及嵌套头前缀检查原样保留，并覆盖空和单字节载荷、非零第二字、尾随数据、所有截断位置、限额和非零起点事务性。测试只验证 Rust 外层读取契约，不验证解码器。
