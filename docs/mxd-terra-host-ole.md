## 第二字和读头边界

- SaveHeader `0x653a1071` 在 `0x653a1084` 将 DWORD `0x0000746c` 放入栈上缓冲，`0x653a108c` 调用写入助手写 4 字节：字节为 `6c 74 00 00`。这是第一个 Write 的高半，不是第二次 Write 的高半；后续另写长度。
- Load `0x653a01ce..0x653a0221` 先读 2 字节比较 `0x746c`，匹配后向同一临时位置再读 2 字节；检查的是读取返回状态。随后向另一位置读 4 字节长度，在分派前原位置被下一轮首字覆盖；此路径没有将第二字用于条件分支或对象状态。非零长度后记录位置并回到首字读取，零长度 `0x653a0247` 将对象 `+0x4c` 和 `+0x1c` 清零并返回。由此只能说该实现忽略此字，不能推断字段业务名称、所有实现都忽略或任意值能在原生运行成功。
- 非 `0x746c` 首字进入图像探测，并可由流位置/长度及 seek 参与处理；不能把单次裸首字探测扩展为本项目已支持的完整旧格式。多个连续 `0x746c` 会重复读头，当前 Rust 读取器只保留最外层声明的原始字节，不模拟此循环或图片解码。
- [介质样本记录](mxd-symbol-ole-20261117-followup.md)的旧版 Africa 模板是局部 BMP 候选、第二字为零；尚未从宿主对象链确认，也未在目标软件中检查。单例不能确定字段语义。

## 非零载荷首 WORD 分派

下表数值均为小端 WORD；首字节检查只选择入口，不保证完整格式合法。空图是长度为零提前返回，不是首 WORD `0x0000`。

| 首 WORD | 入口与本轮核实的静态行为 |
| --- | --- |
| `0x4d42` | `0x6539f482`：读取 `0x36` 字节头；成功且内部 DWORD 为 `0x544c5743` 或 `0x544c5747` 时转共同入口 `0x653a3162`、标识 `0x6537a0e8`；否则转 `0x653a2811`。这比简单称作单一路径 BMP 解码更精确；两个特殊值的完整格式及组件身份未核实。 |
| `0x4947` / `0x6967` | `0x653a3162`，传标识 `0x6537a0c8`；与现有 GIF 识别一致。 |
| `0xd8ff` | `0x653a3162`，传标识 `0x6537a0d8`；对应首字节 `ff d8`，与现有 JPEG 识别一致。 |
| `0x0001` | `0x6539f7dc` 先读 `0x2c` 字节再回退，检查偏移中的 `0x464d4520`。相等时按传入长度读入并调用 `SetEnhMetaFileBits`，成功将对象 `+0x1c` 置 4、`+0x20` 存句柄；否则调用 `0x6539f5b9`，该助手检查头并创建 METAFILE，成功置类型 2。首 WORD 本身不能区分两类。 |
| `0xcdd7` | `0x6539f8ad` 进一步要求 DWORD `0x9ac6cdd7`，再读 18 字节、以剩余长度调用 `0x6539f5b9`；成功后按头中边界与单位数计算对象 `+0x24/+0x28`，单位数为零时直接取差。是带附加头的元文件路径；未对其字段语义、减法下溢与全部异常行为作运行确认。 |
| `0x0000` | `0x653a0137` 调用 `0x6539fd93`；后者读 6 字节，检查保留字为 0、类型为 1 或 2、数量非零，再处理 16 字节目录项；调用成功后前者置对象 `+0x1c` 为 3 并保存句柄。支持图标/光标目录形态，非空图；具体资源选择算法和每种图像编码未闭合。 |
| 其他 | `0x653a03b4` 置 `0x800a01e1`；具体返回仍受后续流定位及错误处理影响。 |

共同入口 `0x653a3162` 按传入标识创建组件，查询接口，传入流并循环处理；未完成各组件及回调的逐函数分析，不能宣称完整解码算法、图像有效性或对象运行行为闭合。`0x6539f5b9` 使用头与元文件句柄并设置类型，`0x653a0137` 的参数以 `0x653a0143..0x653a0174` 汇编确认；Ghidra 对其被调函数的参数列表不完整。

## 可勾选边界、实现与未决

可独立关闭的静态子缺口：**上述特定 2.40.4275.1 文件的 Save 头第二字写零、Load 匹配头时不使用第二字，以及六类首 WORD 的首层分派和上述直接入口行为已定位**。如原 TODO 同时要求第二字业务语义、解码器完整实现、目标 OS 对照或实际图片工程验证，整体仍不能勾选；本轮不修改 TODO。

现有 `src/objects/ole_font.rs` 将 word2 和声明长度内字节原样保留，不解码且不校验未知图片魔数；这是有意保守的读取契约，与原生拒绝未知魔数或重复读头不等价。新证据不足以新增字段名、判定 payload 有效性或引入图像解码，因此没有修改该文件，保留此前工作区改动。既有合成测试含非零第二字、空图、截断、限额；其通过不证明 Windows 行为。

仍需目标 Windows 实际加载的 oleaut32 身份和版本对照、受控不同第二字和各类载荷的保存/加载、失败后流位置及对象状态、组件内部完整解码，以及从宿主对象连通的真实图片工程。ArcMap 10.1 环境暂缺；未在 ArcMap 或 QGIS 打开工程进行人工验收，静态分析不替代运行验证。
