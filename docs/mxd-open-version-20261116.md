## 原生证据与实现

本轮 Ghidra 桥接工具 绑定到 CAB 提取的 ArcMap.exe：PE x86，版本资源 10.1.0.3035，SHA-256 `1fb79eee6b442bd61c44dd3d0864ddfff06b1df882ddc59fb87380bb3ec5af97`，与 `README.md` 适配目标和既有基线相符。Ghidra（经桥接工具） 12.1.4 对保存入口 `0x466fb0` 的观察（Evidence `ev_574061bbf219cc36d6d6eef0e61857e0d76fc636c5688f1b047d8ad75c067a76`）确认：保存路径取得版本属性后，用索引选择资源字符串并写入 String，随后写两字节 short；索引大于 0 时预留并回填 4 字节对象表计数。打开入口 `0x4764d0`（Evidence `ev_c74806811112102157c57ac330a89c4e91a08687e9e2d31208db0496a6baa457`）和版本属性 put `0x42b120`（Evidence `ev_1eb734424214f371857801fcaabe8b71f84861d72ac72a08eec5dd1e42695b00`）与既有 10.1 研究一致。这里是静态代码证据，不是 ArcMap 运行观察。

读取器现有契约是成功后停在已知字段末端，把未知尾部留给调用者。为方便最终版本诊断，`MxdVersionReport` 新增 `unknown_tail` 和 `unknown_tail_truncated`：`identify_version` 依游标位置从原输入复制一次，最多 4096 字节；完整剩余长度仍由 `remaining_bytes` 给出。`read_arcmap_header_10_1`、`read_layout_10_1`、`read_layout_10_8` 的结构字段和游标行为不变。合成测试覆盖尾部原样保留、10.1/10.8 分支、截断计数和条件计数字段短读失败。
