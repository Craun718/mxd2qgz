## 10.8 条件字段的新静态证据

对 10.8.0.12790 SystemCore.dll 重新计算 SHA-256：`48cbd921972d12156119d524f9c3923225fd30795e33c22c65c87db3a6c89aca`，与[第三轮身份记录](mxd-round3-version-object-20261117.md)一致。Ghidra 桥接工具 6.9.0 / Ghidra 12.2 独立 CLI 分析 `0x100708e0`，Evidence `ev_860be423afbea52c6c10d28c68cbe5ad4e96a789487816815255cc80d89dd37b`：输出参数为空时报错；选择参数为零时返回接口 this 相对 `+0x18` 的 4 字节，非零时返回 `+0x24`。证据包在忽略目录 `temp/terra-next-version/systemcore-100708e0.json`，含本机路径，分享前须脱敏。Ghidra 静态分析不是运行观察。

独立 PE 字节检查显示虚表 `0x100ff724` 的 `+0x38` 是既有已核验的 SetStream `0x1006f8c0`，`+0x40` 是 `0x1006f8f0`，`+0x5c` 是上述 `0x100708e0`。与[第三轮](mxd-round3-version-object-20261117.md)已经追到的 ArcMap 保存调用 `+0x5c(0, &value)` 对位，输出为 this `+0x18`。

进一步用 objdump 逐指令核对该虚表 `+0x40` 的写对象路径：`0x1006fe02..0x1006fe20` 以 this `+0x14` 的表和待保存对象键调用查找；已有键时写已有值；缺键时 `0x1006fe86..0x1006fea3` 将对象和 this `+0x2c` 的序号传给 `0x10070cc0` 插入，随后写出序号，成功后 `0x1006fed2..0x1006fede` 自增序号。插入函数 `0x10070d3e..0x10070d70` 及 `0x10070da8..0x10070df2` 在新建链表节点时将表相对 `+4` 加一，已存在键的 `0x10070d94..0x10070da5` 更新值而不增加条目。该表相对 `+4` 即对象流 this `+0x18`。因此上述保存回填值可定性为**对象写表条目数**，不是图层数，也不能将其与 `+0x2c` 下一个键值混为一谈。此结论有静态汇编及既有 Ghidra 桥接工具 调用链支持，未在 ArcMap 中验证；不证明任意损坏或外部生成的输入确为此值，也不闭合额外流尾和所有失败路径。

`ArcMapVersionHeader10_8::write_table_entry_count_candidate` 对已读的四字节提供小端无符号候选值，保留原始字节和未知尾部。它只解释字段，不验证输入来源或对象表实际完整性。独立合成测试覆盖无条件字段、全 32 位保留与未知尾部；它们不是原生运行或互操作验证。未调整公共入口或自动识别策略。
