## 写入、引用与切流

1. `0x48a8a0..0x48a8c8` 调存储对象创建名为 `Version` 的流，输出位置为 `[ebp-0xe98]`；成功后 `0x48a8d2..0x48a8df` 将其赋给 `[ebp-0xea4]`。隔离反编译的 `0x4043a0` 证实该赋值在指针变化时对新引用调用 `+4`、对旧引用调用 `+8`。结合 COM 引用约定可解释为保留独立引用，而不是复制流内容；`0x48a91e..0x48a921` 又把流交给对象流 `+0x38`。
2. 正常创建后，文本写入 `0x48aaf6`、short 写入 `0x48abb0`；保存索引至少 1 时，`0x48ac93` 先以当前位置 Seek 取回填位置，`0x48acb3` 写四字节初始零。之前已静态确定的最终值是对象写表条目数，而不是图层数。索引门控与读取端有符号 short 门控属于不同判断，不应对任意输入直接等同。
3. `0x48cca8..0x48ccd0` 对 `[ebp-0xe98]` 先调用 `0x401a50` 清理旧引用，再以名称 `Maps` 创建另一流；`0x48cdd9..0x48ce16` 将新流传给对象流 `+0x38`。`0x401a50` 在汇编 `0x401a5f..0x401a61` 返回被清零的指针槽地址；伪代码将其返回类型误判为 void。回填仍经独立保留的 `[ebp-0xea4]`，见 `0x48f3ae..0x48f439`。这证明该处正常路径切向 Maps，不能证明此切换以前或其他间接调用没有写入 Version。
4. 尤其在切向 Maps 之前，`0x48b080..0x48b0b0` 向一个间接接口调用传入存储、同一对象流和保存索引；该接收者的实际实现和全部副作用本轮未闭合。对象流原已指向 Version；不能仅凭保存函数内直接引用搜索排除它或其他被调代码的额外写入。后续的 `DocumentDatabase` 是独立命名流，见[前次记录](mxd-terra-chain-version.md)。对所有间接调用、异常路径和最终流长度没有穷举，未知尾部语义仍未定。

## 失败分支：局部调用检查与未检查

| 位置 | 静态观察 | 限制 |
| --- | --- | --- |
| 创建 Version `0x48a8c8..0x48a8cc` | 返回负值时跳到 `0x48ad44`，跳过头部写入，继续调用后续保存逻辑，而非此处立即返回失败。 | 后续可能失败；保存结果及存储是否保留部分文件未验证。不能断言一定成功或一定崩溃。 |
| `String::Write` `0x48aaf6`、short `0x48abb0`、占位 `0x48acb3` | 各调用后检查返回值是否为负；负值走清理并返回 0 的路径。 | 不是事务回滚证明；调用传出的计数字段与部分文件状态未观测。 |
| 取占位位置 Seek `0x48ac93` | 返回后直接准备占位写入，没有局部检查 Seek 返回值。 | 若 Seek 失败，输出位置与后果取决于底层实现，不能推定某个固定偏移。 |
| 回填 Seek `0x48f3de`、取表计数 `0x48f413`、写入 `0x48f433` | 三次调用后均未见局部分支检查返回值；回填写入传空实际字节数指针，然后继续 `0x48f43c`。 | 不证明调用一定失败、失败一定被吞掉至最终成功，也不能推定短写后文件内容。 |

本轮重新核对 10.8 AfCore 导出：`AfStreamWrite` 的各重载指向 `0x100071c0`；汇编直接将参数转交输入接口虚表 `+0x10` 并返回其结果，没有在该包装内补查写入字节数。ArcMap 的 short 和占位分别调用同一重载族，回填调用 `0x549160` 导入的 `AfStreamWrite(..., const long *, ..., unsigned long *)`；最后一个参数为 null。底层 IStream 的实际实现、部分写入语义和上层最终结果尚未运行验证。创建 Version 失败路径可能使保留引用没有正常赋值，但能否到达回填还受中间分支控制，不能据此断言实际解引用结果。
