## IName 的实际 QI 实现

Map `0x7945d350` 对 `LoadObject` 请求 `0x79482c08`；直接读取 Map 该处和 GdbCore `0x70ab84e4` 的 16 字节，均为 IName IID `{4BA33331-D55F-11D1-8882-0000F877762D}`。GdbCore 中 FeatureClassName 持久化表 `0x70ad02dc` 的 GetClassID/Load 归属见 [既有证据](arcmap-10.1-map-object.md)，构造代码 `0x709b3b43..0x709b3b8f` 同时设置主表 `0x70ad0190`；该表首项 QI `0x709b3f50` 比较 `0x70ab84e4` 并返回对象 `+0x10`。QueryTableName 的持久化表 `0x70ac5128` 与类身份见 [既有证据](arcmap-10.1-dataset-name-slots.md)，构造代码 `0x70932142..0x70932179` 设置主表 `0x70ac5038`；其 QI `0x709330d0` 在 `0x7093311b..0x70933146` 比较同一 IID 并返回 `+0x10`。两支均检查了静态机器指令与隔离 Ghidra 反编译，并非仅据类名或类型库推定。QI 路径是原生实现的静态证据，未实际调用目标软件或证明每个流对象都能成功打开数据源。

独立 REA 6.9.0 CLI、JDK 25 和仓库专属 TMPDIR 对 GdbCore 的尝试因 Ghidra 330 秒启动期限返回 `provider_timeout`，没有产生该调用的反编译证据；未修改共享 REA 目标。随后用 `GHIDRA_INSTALL_DIR=/opt/ghidra`、JDK 25、独立目录与复制的既有工程运行 pyghidra/Ghidra 12.2，产物为忽略目录 `temp/terra-nextpass-table/qi_probe.json`，并用 objdump 和 PE 字节交叉核对。产物可能含本机路径，分享前须脱敏。

## 读取器与边界

`standalone_table` 的两个 IName 槽按已证 CLSID 分派既有 FeatureClassName / QueryTableName 读取器，保留对象体；体内未知对象停止时保留已登记外层键和内部停止信息，其他未知类停在对象头前。空槽与回引仍不证明回引对象支持该 IID。已有路径转换、数据源打开和 QI 失败时运行行为没有被模拟。

共同前缀后，读取版本 >=2 的关系对象循环、版本 >=3 的对象槽及压缩序列；原始 token 和展开值都保留。依据 Map `0x7945d630` 的循环，初值为 -2，非负 token 为单个值，负 token 展开为前值之后至其相反数的连续值。严格检查计数、负数取反溢出和展开是否超出声明数量；非法数据报错并回滚，属于比原生更严格的安全策略。版本 >=5 的 int32、版本 >=4 的第二 IName 槽、版本 6/7/9 字符串继续按既有原生字段序读取。

版本 >=10 的 PreJoin 字符串对按 LayerLib 既有 `ReadPreJoinDefExpressions` 证据读取，见 [边界记录](mxd-boundary-luna.md)；版本 >=11 的字符串和对象槽、11/12 的 short 与两个对象槽依原 Load 顺序处理。版本 >=12 的四个 Time 委派复用 `read_time_data_family_10_1`，内部未知对象原位停止。版本 >=14 扩展计数为零时可完成；非零时读取尺寸和 CLSID 作诊断，游标停在该条尺寸字段前，不登记对象、不推测类体。扩展格式见 [保存侧研究](arcmap-10.1-save-side.md)；此处保守停止，并不声称模拟原生按尺寸跳过未知扩展的行为。命名条目、关系条目及尾部对象槽遇到未知新对象同样在其头前停止。非负计数和资源上限、完整短读检查均为本读取器约束，不能等同原生错误处理。

在所有所经槽均为空、回引或已支持且无未知扩展时，版本 0..14 的读取器可以报告体完整；Map 宿主仍按既有策略停在首个独立表，不因此宣称整个独立表集合或转换已闭合。可以独立落账：**两类 IName 的 10.1 静态 QI 与独立表分派；共同前缀之后直至已支持时间族/空扩展的静态读取子集；压缩序列的受限安全展开**。不能勾选完整非空独立表解析、任意扩展或转换、运行时 QI 和实际工程兼容性。
