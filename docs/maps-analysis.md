# MXD /Maps 初步研究

样本大小为 1089536 字节，大小和摘要可用 `wc -c` 和 `sha256sum` 复核；SHA-256 为 `a9b01dfc4fb1dba3db19d53e1f852249862c84570bf2270bd0fff9236daadabf`。外层 `/Maps` 为 152941 字节，`/Preview` 为 180054 字节，`/Version` 为 20 字节。偏移均相对于对应流。原样本和提取数据不纳入仓库。

## 观察与假设

- `/Maps` 的 `0x87a` 开始是 UTF-16LE 字符串 `JZDH`，随后有两个零字节；`0x876` 的四字节小端值为 10，等于该字符串包含终止符的字节数。`0x89e` 的四字节值同样为 10，后接另一个 `JZDH`。这支持“长度以字节计并包括终止符”的局部假设，并不能确认字段类型或对象边界。
- `0x1702` 是一个 UTF-16LE 数据库名称，`0x16fe` 的四字节小端值为 28，等于该字符串包含终止符的字节数；紧随名称之后还有其他数据。不同字符串重复出现类似长度值，但不足以证明所有字符串都采用此编码。
- `0x2d4` 和 `0x33a` 附近出现 `Shapefile 要素类`；`0x3a8` 附近出现 `Shapefile Data`。这些是字符串候选，并非图层计数或对象类型的可靠证据。`0x50a2` 附近出现含坐标系名称的数据库路径，不能据此推导准确 CRS。
- 目前没有足够独立证据确定对象边界、引用关系或图层树，因此未实现对象解析器。

## 复现与后续验证

使用 `mxd2qgz strings <样本>` 查找候选，再运行 `mxd2qgz hex <样本> /Maps 0x860 96` 和 `mxd2qgz hex <样本> /Maps 0x16e0 96` 查看原始字节。此输出中的 ASCII 栏仅用于定位，中文需按 UTF-16LE 解码。实际路径可能包含敏感信息，公开前应脱敏。

下一步应获取同一 ArcMap 版本保存的空白地图以及只增加、重命名或移动一个图层的对照文件，比较流中长度字段与字节变化；同时记录 ArcMap 中的实际图层树和数据源。还需用不同长度、非 ASCII 和空字符串验证长度字段，再研究对象边界和跨对象引用。
