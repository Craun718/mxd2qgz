# Map 对象结束与多数据框顺序读取

ArcMap 10.1.0.3035 x86 Map.dll（SHA-256 `1c0675cc3a99692686a2e9dd8aaa92a68a94b48e9419d8477e33bb57634b1bb8`）的 `Map::Load 0x793ff4d0` 按特定架构版本读取后段。原始指令 `0x7940095c..aab` 证明版本低于 33 时只清理两个已有对象，版本 33 起读取集合。随后 `0x79400ab0` 起的序列在低于 34 时只初始化成员；版本 36、37、38、39、41 及更晚门才启用后续持久化读取。本轮只将已经顺序闭合前段且能越过逐图层遮罩的 Map 版本 29–32、或已读完版本 33 集合的 v33 Map 标为完整。运行中图层/COM 回调没有用本 Rust 代码重现，ArcMap 与 QGIS 未运行。

本机已导出的 `Map/793ff4d0.c`、`Map/79401850.c` 提供字段序；关键版本门与 `0x794015af..79401798` 的最终分派用原始指令复核。Ghidra 在尾端把另一个接口的间接调用误识别为 IStream::CopyTo：原始指令 `0x794016c6..79401713` 从 Map 子对象起做 QI、按 IID 取子接口再以输出指针调用，未传递文件流。没有用流尾长度反向定义 Map 结束位置。

`/Maps` 根循环依据 PageLayout.dll 10.1 的读取端 `0x7b708d00` 与 ArcMap.exe 的写入端 `0x466fb0`（见[对象流记录](arcmap-10.1-object-body.md)）：先数量，再各 Map 对象，最后 4 字节根尾。实现仅在当前 Map 体完整时继续下一头，全程使用同一会话键表。未知后继对象、无效回引、未闭合对象体和短根尾不判为完整。根尾仅在所有声明槽位均完成后解释。为防大对象重复回引造成大量复制，复制的流跨度累计受输入长度约束。

实样从根流顺序对齐（十六进制 /Maps 流偏移）：

| 媒体中的工程 | Map 对象头位置 | 对象架构版本 | 根尾位置与原始值 |
| --- | --- | --- | --- |
| SDK Java LinearRef | `0x4` | 29 | `0x8409`，1 |
| Desktop 10.1 MilitaryPortrait.mxt | `0x4`、`0x49e` | 30、30 | `0x18dc`，1 |
| Desktop 10.1 Utilities.mxt | `0x4`、`0x11d7`、`0x1dcb` | 30、30、30 | `0x29c1`，1 |

上述两个多框实样的 Map 键在各文件内互不相同，根尾之后无字节。新增回归还用 LinearRef 构造第二槽回引、未知后继类和截断根尾；合成场景用于边界测试，不作为原生写出实例。新入口可以区分第二个 Map 前缀中的空间参考回引与空标记；若未在当前数据框证实 CRS 实体，不从键或类标识臆补 CRS。
