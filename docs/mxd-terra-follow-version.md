# Version 保存链续查（2026-11-17）

本文接续 [Terra 版本复核](mxd-terra-next-version.md)，只讨论 10.1 保存属性、旧档加载和 10.8 写入。目标来自安装介质：重新计算 10.1 ArcMap.exe SHA-256 `1fb79eee6b442bd61c44dd3d0864ddfff06b1df882ddc59fb87380bb3ec5af97`，10.8 ArcMap.exe 从 `Data1.cab` 重新提取，SHA-256 `a9a963b9dffbf0cb346c67c98bce0880b7e64363410a788dccb9597cff3c75fe`；pefile 本轮核对均为 PE x86、固定文件版本分别为 10.1.0.3035、10.8.0.12790，与[既有版本资源身份](mxd-version-luna.md)一致。版本资源是声明，摘要是字节身份，不是签名或运行证明。地址为各自静态映像 VA。

## 10.1：对话框后选择值到 AfDoc put

本轮对 EXE 使用 objdump、PE 导入表及虚表字节追踪，并以本地 pyghidra/Ghidra 12.2 和 JDK 25 在仓库独占项目反编译 `0x47cec0`、`0x47f530`；结果分别在 `temp/terra-follow-version/0x47cec0.c`、`0x47f530.c`，是静态伪代码而非原始源码。未连接或改变共享 REA 目标；采用上轮受套接字限制后的定点降级方式。补上此前未解析的间接链：

1. `0x47cec0` 的接收对象为 CMxDoc；`0x47d143` 调用导入的 `AfFileDialog` 构造函数，`0x47d150` 调用 `AfFileDialog::DoModal`。返回值不是 1 时沿 `0x47d15f` 清理并返回 0，不经过下述版本写入。`0x465d67` 直接调用该函数，`0x47cea0` 则以参数 0 包装调用。命令消息映射和所有入口本轮未穷举。
2. 返回 1 后，`0x47d252..0x47d26b` 先以 CMxDoc 虚槽 `+0x14c` 保存旧索引。参数非零、某状态值非 1 且 `*(dialog指针+0x18)>1` 时，`0x47d292..0x47d345` 将该值 2、3、4、5、6 分别映射为 0、1、2、3、4，通过同一 CMxDoc 虚槽 `+0x148` 写入；其他值在此段不调用该写槽。该指针是对话框对象局部 `ebp-0x3c` 中的 `+4` 成员（位于 `ebp-0x38`）；其 `+0x18` 字段的精确类型、与各语言过滤器文本的绑定及 7 等其他值的意图仍需 AfFileDialog 实现或运行复核，不能单靠偏移称作已验证的 UI 版本列表。
3. PE 中 CMxDoc 虚表 `0x54c294` 的 `+0x148` 实读 `0x47f530`，`+0x14c` 为 `0x47f580`。`0x47f530` 在 `CMxDoc+0x1a4` 非空时，取该 AfDoc 的 `+0x124` 接口并调用其虚表 `+0x0c`，传入原值；为空返回 `0x80004005`。既有 [AfDoc 构造及接口虚表证据](arcmap-10.1-native-baseline.md#101-磁盘版本映射属性来源与回填取值2026-11-14)绑定该槽到 `0x42b120`，将值写入 AfDoc `+0x14c`。于是对于所述满足门控的静态分支，对话框返回后的选择值映射已连到 put；该调用结果在局部未检查，且对虚派发的实际类型仍需运行确认。
4. `0x47d347` 调 `0x485690`；返回零时 `0x47d35d..0x47d376` 经同一槽恢复之前取得的索引并返回 0。该函数至少检查当前索引及其他状态；未穷举其失败原因，不能把这一恢复泛化为所有保存失败。DoModal 取消时未到达此处。Ghidra 伪代码还显示通过检查后置标志，并在后续部分返回路径依据该标志恢复旧索引；这不证明所有异常或路径均恢复。现有证据支持关闭**静态的指定对话框分支到 put**这一独立子项；若原条目要求完整命令分发、所有选项与运行结果，仍不应整体勾选。

## 10.1：旧档加载时的候选写入

`0x476c81..0x476cb0` 将已读 short 与存储参数传给 `0x47a3f0`，把返回值作为参数经一个局部接口的虚槽 `+0x0c` 调用；该调用还携带文档及另一个参数。这是新复核的正向数据流，不能仅因虚槽恰为 `+0x0c` 就认定是上面的 AfDoc put：接收者来自 `0x40a8d0` 返回的包装，尚未绑定其具体接口和实现。原 [基线](arcmap-10.1-native-baseline.md#101-磁盘版本映射属性来源与回填取值2026-11-14)“打开旧档候选保持初值”的表述只是有限观察，不能用于排除通过其他接口或模块间接写入。还需追踪该包装的创建、IID、虚表和被调函数及后继调用，并在目标软件中观察打开前后实际索引。

## 10.8：回填与后继流的失败分支

以 [既有 10.8 写表计数证据](mxd-terra-next-version.md)为前提，本轮独立重新提取 EXE 并逐指令核查：

- `0x48a8a0..0x48a921` 创建 `Version` 流存放于 `ebp-0xe98`，并传给 ObjectStream 的 `+0x38`。`0x48ac31` 对保存索引 `>=1` 执行当前位置 Seek 和 4 字节占位写；`0x48acbc..0x48acc0` 检查 AfStreamWrite 返回值，负值走清理并返回 0；紧邻此前的 Seek 返回值未见检查。
- `0x48f37d..0x48f439` 在相同索引门控下调用 Seek、ObjectStream `+0x5c(0,&count)`、AfStreamWrite 回填四字节；从三处调用后到下一处调用或 `0x48f43c` 的局部指令中没有对它们的返回值作条件判断。它们与前述占位写的失败处理不同；这只证明调用点未检查，不能证明底层调用失败一定被忽略到最终成功，也不证明输出一定完整。
- `0x48f43c` 比较索引 4；低于 4 跳过，而不低于 4 时 `0x48f460` 将 UTF-16 常量 `DocumentDatabase` 作为名称传给同一存储对象虚槽 `+0x0c`，结果负值则清理并返回 0；成功后 `0x48f5ce..0x48f5f3` 把新得到的流设给 ObjectStream `+0x38`。这限定了回填之后的一部分工作是**另一个命名流**，不能把这段后续对象序列化直接称为 `/Version` 尾部。单凭局部切流不能证明此后没有再写 Version 或确定全部流结束位置；仍需对 `ebp-0xea4` 保留引用和所有后续写入做完整别名及控制流分析。
- `0x48fa0c..0x48fa29` 后续对存储对象虚槽 `+0x24` 的调用会检查负返回值并走返回 0 的清理路径；成功路径到 `0x48fbe2` 置返回值 1。应继续确认其接口身份及可能的异常、短写、回填失败对最终文件的影响，不能把不同失败路径概括为原子提交或保证成功。
