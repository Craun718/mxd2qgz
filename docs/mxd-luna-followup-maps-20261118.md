# Map 尾部原始指令复核（2026-11-18）

初始 Luna 复核看到 Ghidra 的 `Map/79403d50.c` 将逐图层调用显示为 `FUN_79403bc0(NULL, stream)`；该函数报告删除了数个分支。主审核用 ArcMap 10.1.0.3035 Map.dll 原始指令复核（SHA-256 `1c0675cc3a99692686a2e9dd8aaa92a68a94b48e9419d8477e33bb57634b1bb8`），发现这个 NULL 不是原生行为不变量：

- `0x79403e02` 先清零栈局部 `[ebp-0x14]`；存在图层时，`0x79403e09..0x79403e11` 把该局部地址交给 `0x7941a620`，然后重新读入 ESI。调用在 `0x79403e1c` 压入 **ESI**，`0x79403e23` 再调用 `0x79403bc0`。
- `0x79403de5` 另有依 Map 版本与前一个查询结果选择的跳过分支。因此不能将「初始清零」解释为「调用恒为 NULL」。与[逐图层遮罩的早期指令复核](mxd-terra-round10-mask.md)相符：仍需证明实际图层类型与两类查询的结果，包括 FDO 的聚合路径。
- Map 主函数在逐图层辅助函数结束后有版本门控的 short，继之虚调用，随后才到 String。仓库样本在已有停止点的两个字节恰为 `ffff`，但未证明逐图层调用均不消费该工程的流，不能将这两个字节归属到 short。

主审核撤销了依据反编译中的 NULL 推进游标的试改和相应测试。解析器仍在 `/Maps:0x253be` 保留未知尾部。未运行 ArcMap；本记录没有关闭 Map 尾部或多数据框待办。
