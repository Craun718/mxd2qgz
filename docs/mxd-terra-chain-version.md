## 10.1 命令与对话框来源

1. ArcMap.exe 消息映射 `0x54c158` 后的条目分别将 WM_COMMAND `0xe104`（MFC ID_FILE_SAVE_AS）指向 `0x47cea0`，`0xe103`（ID_FILE_SAVE）指向 `0x465c10`。`0x47cea0` 在 `0x47cea7..0x47ceac` 传 0 调 `0x47cec0`。`0x465c10` 在文档路径为空时通过同一包装弹框，否则调用 `CDocument::OnFileSave`。这是静态消息映射及分支，不能排除其他命令入口或证明运行时实际派发。
2. `0x465c40` 在输入路径为空时把第二参数传给 `0x47cec0`；非空时走文档虚槽 `+0xa0`。`0x414f60` 的 `0x4150dd..0x4150ef` 将其第三个 short 参数传入 `0x465c40`；该函数位于接口表 `0x54406c`，但本轮未闭合该接口身份及它上游的命令或调用者。`0x414cd0` 的两处调用则传 0。因而非零分支已有更上游的静态参数链，但尚不能断言哪个实际 UI 命令触发它。
3. `0x47cec0` 在非模板、参数非零时载入字符串资源 `0x174`，同一 EXE 的英文资源依次为普通 ArcMap Document、8.3、9.0/9.1、9.2、9.3、10.0 六对过滤描述和 `*.mxd`。参数为零时使用仅含普通文档的 `0x175`；模板分支使用 `0x178`。非零参数还提供标题资源 `0xb00e`，英文为 “Save A Copy”。这是该 PE 的英文资源，实际运行资源可能随语言或资源模块不同。
4. `0x47d143` 所用 afUILib 构造器 `0x100eccf0` 将传入的过滤字符串送入 OwnControlsLib `SFileDialog`；后者 `Initialize` 的 `0x100198a6..0x100198b0` 调 `SetFilterString`，`0x10019b9c..0x10019c8d` 将竖线分隔项转为零分隔并设置过滤指针。`0x100ece06..0x100ece15` 把 `SFileDialog::operator tagOFNW*` 返回值保存在 AfFileDialog `+4`；OwnControlsLib `0x10018cb0` 返回自身 `+0xd0` 指针，`SetFilterIndex` 的 `0x10018cd0..0x10018cf8` 将参数加一写到该结构 `+0x18`。结合导出类型 `tagOFNW` 和 x86 结构布局，该字段为 `OPENFILENAMEW.nFilterIndex`。`SFileDialog::DoModal` `0x1001b068..0x1001b08d` 把该指针送入 COMDLG32 `GetOpenFileNameW` 或 `GetSaveFileNameW`；ArcMap 此构造参数为保存模式。与资源过滤项顺序、之前已追踪的 2→0、3→1、4→2、5→3、6→4 及 AfDoc put 相接，静态解释对应 8.3 至 10.0 选项；1 不走该写槽。运行中系统对话框选择及最终文档状态仍未验证。
5. **关键限定**：标准 `0xe104` 命令传 0，而上述版本 put 分支要求参数非零；它也使用单项 `0x175`，不是六项 `0x174`。因此此前「SaveAs 对话框→put」只能称作该函数的**非零参数对话框分支**，不能据此断言标准 MFC Save As 消息本身走到版本选择分支。选项 7 和模板相关特殊路径仍需分别研究。

## 10.8 读写剩余边界

- 读取器 `0x47a250` 在 `0x47a7c5` 把打开的 Version 流设给对象流；`0x47a99a..0x47aa00` 对有符号 short ≥12 从原始 Version 流读取四字节，再将值传对象流 `+0x54`。`0x47a9c4` 读调用后没有局部 HRESULT 检查，且传入的实际读取字节数指针为空；本观察不证明短读时的值或运行结果。之后经接口调用传递同一对象流及存储对象，后续对象流读取可能换底流；尚未穷举被调实现，不能将所有后续读归给 Version，也不能证明未读取额外尾部。
- 写入器 `0x48a380` 将最初 Version 流复制保存在 `ebp-0xea4`，而 `ebp-0xe98` 随命名流创建而复用；`0x48f3ae..0x48f439` 从保留引用定位并回填四字节。重新检查本函数反汇编中该局部变量的引用，回填后的直接用途为清理引用（正常路径 `0x48fd04..0x48fd0a`）；`0x48f43c` 以下按索引选择是否创建 DocumentDatabase 并重新设置对象流。这个有限的直接引用检查缩小了尾部范围，但对象流、存储接口及其他别名可能间接访问流，不能由此证明所有路径没有额外 Version 写入，也不能证明最终流长度或原子性。
- 原有结论仍成立：回填的 Seek、取计数及写入三个调用点未做局部返回值判断；创建后继流和后续存储调用有各自失败分支。尚需完成对象流切换和间接别名的控制流审计、读取器委派体及异常/短写处理，才能闭合完整读写尾部。
