# MXD → QGZ 分阶段实施路线

来源：用户批准的 35 步提交计划，2026-11-12。基线 `721ad49`，工作区干净，
`cargo fmt --check` 和 24 项测试通过。每步验证后独立提交，使用中文
Conventional Commits，同步 TODO，不推送。研究复杂时可拆分证据提交。

## 依赖与约定

原生证据 → 解析 → 输出 → 软件目视验收。未知格式阻塞相应实现，
只记录实际发现和未知项，继续独立工作；不以推测填满提交序列。
首要研究目标是 Desktop 10.8；10.1 需要独立证据，候选文本不证明兼容。
源码注释中文；先读 maps-analysis，再改规则。研究记录包含目标摘要、
版本、函数地址、证据 ID、结论及未知项；DLL 地址与流内偏移分开记录。

保持现有五个诊断命令和 Python inspect/read_stream 兼容，不增加 Python
转换 API。Rust 按文档解析、模型、QGZ 写入分层，写入器可独立使用构造模型验证。
模型逐步加入版本、源位置、对象身份、样式、布局；未知信息不由默认值掩盖。

Rust 改动运行 cargo fmt --check 和 cargo test；CLI 改动补端到端测试并按
README 验证。解析测试覆盖可构造正常输入、截断、非法长度、溢出、引用及嵌套
边界；输出测试检查 ZIP/XML、转义、路径、防覆盖和失败清理。
自动测试、QGIS API 加载、软件人工目视验收分别记录，不能替代。

原始 DLL、提取流及完整诊断留在忽略的 temp/。公开记录先脱敏。
无人工环境时记录完整版本缺口及“未验证”，保留对应 TODO。
