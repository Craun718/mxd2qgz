## 本轮定点核验

### 113：三个字段逐项审证

本轮核验 `Map.dll` PE 固定版本 `10.1.0.3035`、SHA-256 `1c0675cc3a99692686a2e9dd8aaa92a68a94b48e9419d8477e33bb57634b1bb8`，与既有 Map 基线一致。REA 6.9.0 / Ghidra 12.2 独立 CLI 对 `0x7940fd80` 产生伪代码证据 `ev_cae0d6cd2dbf924f6551c45e3d1b5fcea0a0baac8ba135e85badf4989c8571`，原始输出保存在忽略目录 `temp/`；辅助反汇编为 objdump。地址是此 PE 静态 VA，不是运行地址。

- `+0x19c`：Load/Save 读写 short，既有复核已对位；业务属性名、对应接口 getter/setter 未证。**PARTIAL**。
- `+0x200`：Load `0x793ffb98..0x793ffbc1` 读 8 字节 double 后，以寄存器 ESI=`edi-0x68` 调 `0x7940fd80(0, value)`；该函数读写 `[ESI+0x268]`（等于加载侧 `edi+0x200`），并向取得的另一个接口 `+0x78` 传递该值。另有 `0x793efa90` 包装将其作为 double 参数调用同一函数，调用时标志为 1；该入口出现在虚表地址 `0x79486f6c`。这确认数值不仅保存，还传播至另一个接口，但接口身份和该槽名称尚未建立，不能将业务名定为参考比例尺。**PARTIAL**。
- `+0x264`：Load/Save 读写 short，既有复核已对位；业务属性名、对应接口 getter/setter 未证。**PARTIAL**。

三个成员的业务名均未达到可接入的确证标准；也没有追坐标变换或照明对象。另须注意 Load/Save 对象内部偏移与对外接口 this 指针可能不同，不能单凭相同数值偏移绑定接口。

### 88：10.8 Version 条件回填的汇编子链

10.8 ArcMap.exe PE 固定版本 `10.8.0.12790`，SHA-256 `a9a963b9dffbf0cb346c67c98bce0880b7e64363410a788dccb9597cff3c75fe`，与第二轮一致。对保存入口相关代码使用 objdump 辅助复核：`0x48a8d2..0x48a921` 将刚创建的 Version 流连接到对象流；`0x48ac31..0x48acb9` 在版本索引至少 1 时记录流位置并写入 4 字节占位；`0x48f37d..0x48f439` 同一门控下使用保存的位置 Seek，调用同一对象流虚表 `+0x5c(0, &value)`，将输出的 4 字节写回该流。它比第二轮证实了回填的具体来源路径；`+0x5c` 的 10.8 内部实现、资源文本表和整个流尾仍须独立核对，不能仅借用 10.1 实现断言完整语义。REA 6.9.0 / Ghidra 12.2 伪代码证据 `ev_2de8ccc6d92d454438287b9c7f34387ea2a876e3f099aefddcc564482269afd6` 将 `0x48f37d` 归入保存函数 `0x48a380` 并显示回到保存位置后对流对象调用虚槽再写入；其长函数提示反编译重启次数超限且误标接口槽，故具体参数、槽偏移与流身份以本轮汇编为准。

同一 10.8 REA 伪代码还显示 `AfStreamGetSaveVersion(index, 12, 0x554ff0)`；本轮从对应 PE 读取该地址的 12 个 little-endian signed short：`[10, 13, 14, 16, 18, 19, 20, 21, 22, 23, 24, 25]`。保存索引 0..10 对应资源 ID 依次为 `0x14d, 0x173, 0x186, 0x11a, 0xe804, 0xe82b, 0xe82c, 0xe82d, 0xe82f, 0xe830, 0xe831`，其余索引走 `0x193`。静态解析该 EXE 英文资源（lang `0x409`），依次得到 `8.3, 9.0, 9.2, 打印错误文本, 10.0, 10.1, 10.3, 10.4, 10.5, 10.6, 10.7`，default 为 `10.8`。资源句柄可能取本地化模块，不能将英文表当作所有环境的实际输出；索引 3 的异常文本也不能映射为 `9.3`。PE 资源解析只是静态文件观察，非运行验证。

### 101：10.8 切流实现重新取证

`SystemCore.dll` PE 固定版本 `10.8.0.12790`、SHA-256 `48cbd921972d12156119d524f9c3923225fd30795e33c22c65c87db3a6c89aca`。独立 REA 6.9.0 / Ghidra 12.2 反编译 `0x1006f8c0`（`ev_0159525fab85a7c8bec16bd1a39007b4f94487bb5caf7dbfbcced58932030f85`）：比较接口相对 `+0x10` 的旧流与入参；不同时保存新指针、对非空新流 AddRef、对非空旧流 Release，然后返回 0。此函数不修改引用表或其计数，与已证 10.1 SetStream 行为一致；并不能由此推断不同文件格式的全部对象体兼容，也不能排除其他显式重置入口。
